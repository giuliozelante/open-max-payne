# Distance fog and the back plane

## Sources

- **`levels.txt`, VERIFIED (retail text):** each level's `[Properties]` carries `Fogging`, `FogColor`
  (0..255 RGB), `FogStart` and `FogEnd` (28 blocks set `Fogging`). The house (`part0_level1`) sets
  `Fogging = false`. The startup intro sets 2000 to 5000 and notes "Level adjusts on the fly".
- **`GM_ChangeFog(0xRRGGBB, frontPlane, backPlane, time)`, VERIFIED:** documented in the MaxED
  `messages.htm` and `MaxEDInit.txt`. The docs say it "changes the fog color, front plane distance,
  back plane distance and how fast the fog should change", and warn against continuously animated
  fogs. Calls in the shipped levels:

  | Level | Calls |
  |---|---|
  | Part2_Level0 | 7 |
  | Part2_Level3 | 3 |
  | Startup_level | 2: `0x141414, -700, 700` and `-200, 400` |
  | end_combat | 2 |
  | Part3_Level1 | 1 |
  | Part1_Level1 | 1 |
  | Part0_Level1 | 1: `0x0, 1000, 1000, 0` |

  Negative front planes occur (the fog has already begun at the eye).
- **`globalconfig.txt` `[camera]`, VERIFIED:** `FrontPlaneDistance = 0.05` and
  `MinimumBackPlaneDistance = 10.0`.

## Engine

- **Seeding:** `LevelsTxtEntry.fog` seeds `LdbScene.fog`.
- **`GM_ChangeFog`:** it replaces the fog at once, or fades every value linearly over `time` seconds
  (`step_fog`). With no fog set yet, the new fog applies at once.
- **Fog formula:** linear in view depth, `k = clamp((z − start) / (end − start), 0, 1)`; the colour
  is mixed toward `FogColor` by `k`. The software renderer fogs every pixel that has a depth after
  rasterisation, so the sky stays clear. The wgpu shader applies the same formula per fragment.
- **Back plane:** the fog does not set it; see "Back plane, read from the binary" below.

## HYPOTHESIS / UNKNOWN

- **Fog formula:** linear table fog by view depth. The retail D3D fog render states have not been
  read yet.
- **Sky:** that the world sphere is drawn without fog.
- **Translucent pixels:** in software, blended polygons that do not write depth take the fog of the
  surface behind them.

## Back plane, read from the binary (2026-11-04)

**VERIFIED (static, `MaxPayne.exe`):** the game camera's back plane is recomputed every frame and has no link to
the fog. `0x67a4de` starts from `[+0x5cc]`. The loop to `0x67a664` walks the list at `[+0x5ec]`. For each entry it
transforms the bounding-sphere centre (`0x63aa50`, entry object at `+0x6c`, matrix at `+0x1c`) and adds the sphere's
radius (`0x63ab00`) to the distance, keeping the largest value in `[+0x5c8]`. `0x6777b3` then passes `[+0x5c8]` to
`P_Camera::setBackPlane`.

**STRONGLY SUPPORTED:** `[+0x5cc]` is `MinimumBackPlaneDistance`. It is set through `0x6776f0` from a config getter
(`0x5e53d0`, callers `0x451234`, `0x451391`) next to the front plane, and the plane only ever grows from it.

**HYPOTHESIS:** the `[+0x5ec]` entries are the meshes or rooms in view.

**Measured (retail frames against the data):** the statue is a two-polygon billboard (material 113) at z = −1137,
714 m from the camera at z = −423, under `GM_ChangeFog(0x141414, -700, 700, 0)`. Retail shows it. The engine had
used the fog end as back plane, which culled it by 14 m. Past the fog end a surface now draws in the fog colour,
which should read as a dark shape against the retail sky (about 26 grey here, against the fog's 20).

**Engine:** since the plane always clears what is in view, `render3d::FAR_Z` is only a depth range. The fog no
longer clips anything.
