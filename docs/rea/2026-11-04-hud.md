# HUD: how the original reads its data (2026-11-04)

The HUD is defined by retail data. This note records how `MaxPayne.exe` and `e2mfc.dll` read it, so the engine
reads the same files the same way. Addresses are PE i386, ImageBase `0x400000` (`e2mfc.dll`: `0x10000000`).

## Files

- **VERIFIED:** `data/hud/hud.txt` (string `0x878f74`) lays out everything in 640x480 space. `MaxPayne_HUDMode` loads
  it: the keys are registered near `0x4adad4` to `0x4ade8c`, and the sections load from `0x4b13f4` to `0x4b20b8`.
- **VERIFIED:** `data/hud/bitmaps/` is in `x_data.ras`. `data/hud/bitmaps/weapons/` (35 files) is in the localized
  `x_<lang>.ras`, because the weapon names are in the images. The `+` between the ammo counts is in those images too.
- **VERIFIED:** the crosshair is not in `hud.txt`. Each weapon's `.txt` names a mesh under `[Crosshair]`:
  `database/weapons/crosshairs/dot.kf2` (13 weapons) or `invisible.kf2` (4), with `[CrosshairAttributes]` from
  `database/shooting.h`. The binary has an `X_Crosshair` class and the `C_DisplayCrosshair` message.

## `MaxPayne_HUDMode` members (VERIFIED, loader and update)

| Member | Holds |
|---|---|
| `+0xfc` | `[Health]` `[Sprite]`, the pain fill |
| `+0x100` | `[Health]` `[BackgroundSprite]` |
| `+0x104` | `[Health]` `[RegenerationSprite]` |
| `+0x108`, `+0x10c` | `[SlowMotion]` `[Sprite]`, `[BackgroundSprite]` |
| `+0x110`, `+0x114` | `AmmoInPocketText`, `AmmoInClipsText` |
| `+0x12c`, `+0x13c`, `+0x14c` | Hourglass colours |
| `+0x19c`, `+0x1a0` | `LowHealth`, `ShowInverseHealth` |

Sprites carry a value at `+0x110` set by the loader (regeneration 5, background 3). HYPOTHESIS: draw order.

## Update, `0x4aee20` (VERIFIED)

**Hourglass.** With `g` the slow-motion level (`0x421ae0`), the foreground's height is `height * g` and the top of
its texture coordinates is `1 - g`, so it shows the lower part of the bitmap. Both sprites are refreshed every
frame. The colour is `+0x13c` while active (`0x421af0`). Otherwise it is `+0x12c` when the level is above `0x421b00`,
else `+0x14c`. STRONGLY SUPPORTED: those are `ColorActive`, `ColorNormal` and `ColorUnavailable`, as the slots
follow the three colour loads at `0x4b171b`.

**Health.** With `h` the normalized health (`0x421e90`) and `r` the pending regeneration (`0x421ea0`):

1. When `h <= LowHealth`, the background and the fill are refreshed. `LowHealth = 1.0`, so that is always.
2. `k = h`. With `ShowInverseHealth`, `k = min(h + r, 1)`, then `k = 1 - k`.
3. The fill's height is `height * k` and the top of its texture coordinates `1 - k`.
4. When `r > 0`, the regeneration sprite shows above it (`0x4af11a` on).

So at full health the fill has no height and only the pale figure shows, as in retail frames.

## Fonts (VERIFIED, `e2mfc.dll`)

`P_Font::validate` (`0x10001e60`) walks the colour bitmap's first row for 256 characters: it skips black pixels,
stores the start of each coloured run, and stores `run + 1` as the width (`+0x50 + code * 4`). The height (`+0x4c`) is
the bitmap's height minus 2. `P_Font::getViewportSize` (`0x10001dc0`) sums the widths with no spacing.

**Measured:** a texel is one unit of 640x480 space. In retail frame `original/0104`, a digit pitch of 8 is 24 px across
1920, and the bright rows of a digit span 29 px of 1080. `18` ends at x = 582 and `99` starts at 597, on the anchors.

## Player weapons

- **VERIFIED (data):** the level scripts hand out the player's weapons. `Part0_Level1` runs `player->c_removeallweapons(empty)`
  and `c_pickupweapon(painkiller)` first, then later `c_removeallweapons(beretta)`, `c_setinfiniteammo(beretta, false)`,
  `c_pickupweapon(painkiller)`, `c_pickupweapon(beretta)` and `c_pickupammo(beretta, 99)`.
- **VERIFIED (docs):** `messages.htm` gives `C_RemoveAllWeapons(%s)`, `C_PickupWeapon(%s)`, `C_PickupAmmo(%s, %d)` and
  `C_SetInfiniteAmmo(%s, %d)`.
- **STRONGLY SUPPORTED (community tutorials `npc-helper`, `npc-helper2`):** `C_RemoveAllWeapons(x)` strips the character and
  gives `x` with unlimited ammo; `Empty` gives nothing. That matches `hud.txt`'s `UnlimitedAmmoText = "-"` and explains
  the house script's `c_setinfiniteammo(beretta, false)`.
- **VERIFIED (data):** each `database/weapons/<name>.txt` has `WeaponID`, `Clipsize` and `Pocketsize`, the sizes
  mostly through `shooting.h` (`BERETTA_CLIPSIZE = 18`, `BERETTA_POCKETSIZE = 162`).
- **HYPOTHESIS (retail frame):** `C_PickupWeapon` of a weapon already carried adds nothing. The house script does
  that and the HUD reads `18 + 99`. A pickup puts a full clip in hand. Not read from the handlers yet.
- **HYPOTHESIS:** the engine reloads at once from the pocket when the clip is empty. Retail plays a reload animation
  (`ReloadAmount = -1` in `beretta.txt`), and picks weapons through `weaponpriority.txt`.
